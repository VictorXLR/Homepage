1.58 billion tokens later: auditing everything I have built with AI

Most developers have no idea how many tokens they burn because the meter is hidden behind a $20 subscription or a scatter of API dashboards. I queried every local database on my machine to see where 1,578,123,329 tokens actually went.

Victor Popoola · November 22, 2026 · 10-minute read

After writing Weblog 002 on how I coordinate AI agents in the terminal, I wanted to answer a simpler question: how many tokens have I actually consumed since I started building software with AI agents, and what did all of that compute produce?

Because terminal-native harnesses persist their full conversation state and turn-by-turn API telemetry in local SQLite databases and JSONL logs on disk, you don't have to guess. You can join the tables, sum every prompt, cache read, reasoning trace, and completion token, and map the ledger back to the exact projects that consumed them.

Across fourteen months of tracked agent history (September 2025 through November 2026), the grand total comes out to 1,578,123,329 tokens across 736 coding sessions and more than 15,000 agent turns. Here is the full accounting of the harnesses, the token economics, and every project I have built along the way.

Scope and evidence. Token counts were aggregated directly from local telemetry stores across four coding harnesses (ForgeCode, OpenCode, Codex CLI, and Claude Code) plus local LM Studio inference logs as of November 22, 2026. Figures exclude untracked browser chat tabs and background IDE autocomplete (where Cursor recorded 1,280 accepted code blocks across 489 scored commits without raw token counts).

01 / The 1.58-billion-token ledger

Before settling on my current terminal workflow, I rotated through four main agent harnesses. Every one of them logs token usage slightly differently, so normalizing them into a single table makes the distribution obvious:

1. ForgeCode / 769,879,918 tokens (48.8% of total)

Volume: 401 conversations (including 153 spawned sub-agent sessions) and 7,351 API turns.

Token split: 764,458,295 prompt tokens (of which 699,311,648 were cache hits—a 91.5% cache ratio) and 5,421,623 completion tokens across 1,683 modified files (+214,686 / −35,843 lines).

Role: My primary daily driver since mid-2026 for multi-agent orchestration, parallel file-ownership tasks, and heavy full-stack refactors.

2. OpenCode / 344,167,268 tokens (21.8% of total)

Volume: 239 sessions and 5,509 assistant turns.

Token split: 49,215,913 uncached input tokens, 285,375,180 cache-read tokens, 4,580,295 cache-write tokens, 4,522,068 output tokens, and 473,812 reasoning tokens.

Role: My bridge harness from late 2025 through mid-2026, used heavily to test frontier models side by side—from Claude Opus and Sonnet to Qwen3-Coder, GLM-4.7, Kimi K2.5, DeepSeek, MiniMax M2, and local MLX/LM Studio models.

3. Codex CLI / 325,478,780 tokens (20.6% of total)

Volume: 88 threads across OpenAI reasoning and coding models.

Role: My earliest high-volume coding agent in Autumn 2025 and my go-to second opinion for gnarly state-management loops, codebase comprehension maps, and Swift/macOS desktop debugging.

4. Claude Code / 138,597,363 tokens (8.8% of total)

Volume: 8 long-horizon sessions and 2,230 turns.

Token split: 1,980,773 uncached input tokens, 126,389,012 cache-read tokens, 9,233,735 cache-creation tokens, and 993,843 output tokens.

Role: Concentrated marathon sessions for hardware MIDI controller integration, terminal multiplexer migrations, and web design passes.

02 / Why 1.58 billion tokens didn't cost a fortune

If you priced 1.58 billion tokens at standard 2024 frontier rates ($15 per million input tokens and $75 per million output tokens), this ledger would represent more than $24,000 in raw API billing. In reality, my direct metered pay-as-you-go API spend across ForgeCode and OpenCode totaled $325.43 ($258.53 in ForgeCode and $66.90 in OpenCode), supplemented by flat-rate Pro/Max subscriptions and local Apple Silicon inference.

Three structural shifts in how coding agents consume tokens explain that 70x gap:

  • Prompt caching is the entire game (90.1% cache hit rate): Agent loops re-send the system prompt, tool definitions, file trees, and conversation history on every single turn. Out of the 1.25 billion tokens where turn-level cache telemetry was recorded, 1.11 billion tokens (90.1%) were served from provider prompt caches at a ~90% discount, while only 11.4 million tokens (0.9%) were newly generated output tokens. For every 1 token an agent writes, it reads roughly 110 tokens of context.
  • Tiered model routing: You don't need a heavyweight flagship model to run git status or read a JSON schema. Routing high-frequency tool dispatch to fast, low-cost coding models (such as glm-4.7-flash, qwen3-coder, or kimi-k2.5) while reserving frontier reasoning models for architecture planning cuts per-session cost by an order of magnitude.
  • Offloading iteration loops to unified memory: Anytime a project needed tight feedback loops—like generating hundreds of diffusion images, testing recursive task breakdown in a TUI, or running vision-language captioning—I pointed the harness at local Apple MLX, PyTorch MPS, or llama.cpp servers where the marginal token cost is zero.

03 / How my usage evolved over fourteen months

Looking at the monthly token curve shows three distinct phases in how I work with AI:

  • Phase 1 — Single-thread exploration (Sept–Dec 2025 · 285.9M tokens): Started at 118.0M tokens in September 2025 with Codex CLI, dipped to 9.7M in October, and climbed back to 47.4M in November and 110.8M in December as I adopted OpenCode to build encrypted messaging prototypes, browser RL models, and local Rust inference engines.
  • Phase 2 — Focused local & systems builds (Jan–Aug 2026 · 199.4M tokens): After a quiet January and February focused on non-agent coding, usage scaled steadily from 14.9M tokens in March and 13.5M in April to 44.0M in May, 45.8M in June, and 75.6M in August as I built native iOS/macOS utilities, Go CLI tools, and local image generation pipelines.
  • Phase 3 — Multi-agent terminal orchestration (Sept–Nov 2026 · 1,093.1M tokens): Moving full-time into parallel sub-agent workflows in ForgeCode pushed monthly volume to 342.7M tokens in September 2026 and a peak of 689.7M tokens in October 2026 (across 329 sessions and 6,488 turns), followed by 60.6M tokens through November 22. Parallelizing read-only research agents alongside scoped implementation workers multiplied token throughput—and shipping speed—by 5x.

04 / Reviewing everything I have built so far

When you group the 1.58 billion tokens by repository, they cluster into six engineering domains. Here is a complete review of what those tokens actually built, ranked from my largest multi-hundred-million-token flagships down to weekend hardware and compiler experiments.

1. Full-stack consumer & mobile apps (515.1M tokens)

Charms · 386.4M tokens (257 sessions across all 4 harnesses): My largest project by far—consuming nearly a quarter of every token I have ever spent. Charms is a React Native (Expo Router), Zustand, and Supabase digital wardrobe and social marketplace. Over fourteen months, agents helped take it from initial closet cataloging and camera background cleanup through 19+ PostgreSQL Row-Level Security migrations, Google/Apple/phone authentication, virtual trip packing, a Cloudflare Workers AI fashion vision pipeline, and a full role-based content moderation suite.

Slize · 98.1M tokens (37 sessions): An NYC craft cocktail notebook and playable neighborhood bartender shift game built with Expo, React Native Reanimated, and Rough.js. Agents helped build the 120Hz haptic Cocktail Dial, the hand-drawn vector ink aesthetic, the offline shift-pouring game engine, and the Cloudflare Worker recipe backend.

New Friend Store · 17.6M tokens: A free community item-sharing platform built with Next.js 15, TypeScript, Supabase, and OpenNext on Cloudflare Workers with an editorial, high-contrast catalog layout.

Punk · 5.8M tokens: An early Expo mobile prototype blending daily habit tracking with cozy farming-RPG progression mechanics.

After Party · 5.3M tokens: A privacy-first native iOS social memory and event log built in Swift.

Felloff & GlitchFX Pro: A Next.js internet culture analytics archive and a React Native computational glitch-art photo studio.

2. Developer tools, agent harnesses & visual canvases (307.9M tokens)

Diorama · 193.9M tokens (28 sessions): My second-largest token sink. Diorama is an interactive Excalidraw-style whiteboard harness that binds to a local Git repository, indexes files and symbol call graphs into visual architecture maps, and lets an LLM agent modify code directly from the canvas over a Python/Bun WebSocket bridge.

Modelo (cowyo2) · 61.5M tokens (10 sessions): A modernized, zero-friction collaborative wiki and interactive CodeMirror/Python notebook frontend built atop a fast Go + SQLite backend.

Homepage (this site) · 24.7M tokens (14 sessions): Interactive WebGL seascape shaders, custom editorial typography, and these long-form engineering retrospectives.

ForgeCode contributions · 20.2M tokens (29 sessions): Dogfooding ForgeCode to build and test features inside ForgeCode itself—specifically implementing OpenRouter flex/service-tier provider routing and interactive CLI controls.

LiveDOMSync · 8.1M tokens: A drop-in browser DevTools inspector and React-Scan-style overlay that highlights live DOM mutations and syncs in-place text edits back to source files.

MadeWithJelly & Infinite-Web · 3.2M tokens: A Three.js / React Three Fiber interactive 3D jelly landing page and an LLM web-simulator that generates complete interactive websites from synthetic URL prompts.

3. Local computer vision, diffusion & browser RL (116.6M tokens)

SAM-3 pipeline & Image Cutout · 36.8M tokens: Local Python server and browser segmentation tools built around Meta's Segment Anything Model for one-click object isolation and asset extraction.

HRM Game & Flappy-ML · 34.6M tokens (13 sessions): A generalizable two-timescale Hierarchical Recurrent Model (HRM) running reinforcement learning and neuroevolution inside browser Web Workers with TensorFlow.js across Pac-Man, Flappy Bird, and a JS-DOS Doom environment.

Turbo-Term (z-image-turbo) & Flux-UI · 35.0M tokens (18 sessions): Local Apple Silicon image generation tools—rendering Z-Image-Turbo directly inside Ghostty terminal panes via the Kitty graphics protocol with a warm MLX worker, plus a custom tldraw node canvas driving 4-step distilled FLUX.2-klein-9B over FastAPI and PyTorch MPS.

FastVLM WebGPU · 9.5M tokens (9 sessions): Real-time local video captioning running Apple's FastVLM vision-language model completely client-side in the browser via WebGPU.

Field RL Canvas (stem) · 2.3M tokens: Browser-local ONNX reinforcement learning and a pure multiscale NYC city and subway ecosystem simulation with real-time held-out policy evaluation.

4. Systems networking, cryptography & native utilities (218.2M tokens)

Secretchat · 63.8M tokens (19 sessions): An end-to-end encrypted messaging platform with offline-first mobile support, client-side cryptographic key management, and alternate-reality game (ARG) mechanics, coordinated using the beads issue tracker.

Boring Notch · 38.2M tokens (4 sessions): Custom multi-face idle animations, visibility state machines, and media controls for the macOS MacBook notch.

SightVibe · 29.1M tokens: A native macOS utility turning the MacBook Touch Bar and screen into an interactive guided breathing and rest-timer visualization.

BitChat Nostr Bot · 27.2M tokens (5 sessions): A Swift bot implementing Nostr WebSocket relay transport, cryptographic event signing, geohash channel discovery, and offline whitepaper auto-responders.

Tree Hugger · 12.2M tokens: A native iOS Swift app indexing and clustering nearly 700,000 NYC street trees from Socrata open data.

btcd · 10.7M tokens: A zero-bundler WebAssembly runtime and binary LEB128 section inspector with hand-written WebAssembly Text (.wat) simulations.

05 / What the token ledger taught me

Auditing 1.58 billion tokens across forty-plus repositories makes a few patterns impossible to ignore:

  1. Tokens are a proxy for context breadth, not code volume. My highest-token sessions weren't the ones that generated the most lines of code; they were the sessions where an agent dragged a 90,000-token conversation history across fifty turns while debugging a subtle hardware or state-synchronization bug. Keeping sessions short and scoped around a written plan cuts token burn in half.
  2. Prompt caching makes modular architecture cheaper. Because 90% of agent tokens are cache reads of your existing codebase and tool definitions, clean file boundaries don't just help humans—they keep the prefix cache hot and prevent agents from re-reading monoliths on every turn.
  3. The best projects combine cloud reasoning with local execution. Cloud agents are unmatched at orchestrating multi-file refactors across TypeScript, Go, Rust, and SQL. Local Apple Silicon models are unmatched when you want an application itself to think, see, transcribe, or generate images with zero ongoing API tax.

One and a half billion tokens sounds massive on paper, but spread across fourteen months of continuous shipping, it is simply the new unit of software iteration—the modern equivalent of compiler cycles.
